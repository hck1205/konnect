# 디자인 원칙

일반적인 "깔끔하게, 일관되게" 같은 말은 적지 않는다.
**konnect가 다른 커뮤니티와 다르게 판단해야 하는 지점**만 원칙으로 남긴다.

## 1. 불안한 사람이 읽는 화면이다

사용자는 비자가 만료되기 직전이거나, 보증금을 잃을까 걱정하며 이 화면을 본다
([도메인](../10-domain/)). 즐거운 브라우징이 아니다.

- 채도 높은 색, 통통 튀는 모션, 마케팅 톤을 쓰지 않는다
- 브랜드 색을 **차분한 teal**로 고른 이유가 이것이다
- 강조는 색이 아니라 **위계와 여백**으로 만든다

## 2. 제2언어로 읽는다

영어가 모국어가 아닌 사용자가 다수다 ([타깃](../00-overview/03-target-users.md)).
글을 훑지 않고 **한 줄씩 읽는다.**

- 본문 `line-height`를 넉넉히 잡는다(1.625) — 일반적인 1.5보다 크다
- 본문 최소 크기는 **16px**. 12px는 메타 정보에만
- 한 줄 길이를 제한한다(약 70자)
- 아이콘만으로 의미를 전달하지 않는다. **항상 텍스트 레이블을 동반**한다

## 3. 한글과 영문이 한 문장에 섞인다

`Alien Registration Card (외국인등록증)` 같은 병기가 관례다
([i18n 전략](../30-architecture/06-i18n-strategy.md)).

- 폰트 스택에 **한글 폴백을 명시**한다. Geist에는 한글 글리프가 없다
- 두 문자 체계의 크기 차이를 감안해 본문을 키웠다
- 한국어 원문은 **복사 가능**해야 한다 (사용자가 검색창에 붙여넣는다)

## 4. 정확성의 등급이 시각적으로 보여야 한다

[콘텐츠 리스크 정책](../10-domain/10-visa-immigration/03-content-and-risk-policy.md)의
R1/R2/R3가 화면에서 구분되지 않으면 정책이 아니라 문서일 뿐이다.

- R1 고지는 **본문 가까이**, 무시하기 어려운 대비로
- "개인 경험"과 "규정"이 시각적으로 다른 블록이어야 한다
- **최신성**(`lastVerifiedAt`)은 색으로 상태를 드러낸다 — 신선/노후/오래됨

## 5. 접근성은 옵션이 아니다

취약한 위치의 사용자를 대상으로 한다
([안전과 신뢰](../10-domain/60-social-community/02-safety-and-trust.md)).

- 모든 텍스트 조합은 **WCAG AA(4.5:1)** 를 넘는다. 측정해서 확인한다
- 포커스 표시를 **전역 기본값으로** 보장한다. `outline: none` 금지
- `prefers-reduced-motion`을 존중한다
- 색만으로 정보를 전달하지 않는다 (색 + 아이콘/텍스트)

## 6. 검색으로 들어와 상세 페이지에 착지한다

주 유입이 검색이다 ([J1](../20-product/03-user-journeys.md)).

- **상세 페이지가 첫인상**이다. 홈이 아니다
- 로그인 벽을 읽기 앞에 세우지 않는다
- 상세 페이지는 그 자체로 완결되어야 한다 — 맥락(태그·최신성·작성자)이 화면 안에 있어야 한다

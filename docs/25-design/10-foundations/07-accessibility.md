**WCAG 2.1 레벨 AA.**

## 이미 시스템에 내장된 것

토큰과 전역 스타일이 처리하므로 컴포넌트가 신경 쓰지 않아도 되는 것들.

| 항목 | 어디서 |
| --- | --- |
| 텍스트 대비 4.5:1 | 색 토큰 (전 조합 측정 완료) |
| 입력 테두리·포커스링 3:1 | `border-interactive`, `focus-ring` |
| 포커스 표시 | 전역 `:focus-visible` 규칙 |
| 모션 감소 존중 | 전역 `prefers-reduced-motion` |
| 본문 16px + 넉넉한 행간 | 타입 스케일 |

## 컴포넌트가 지켜야 하는 것

시스템이 대신 해줄 수 없는 것들.

### 1. 포커스를 지우지 않는다

```css
/* ❌ 절대 금지 */
outline: none;
```

대체 표시 없이 `outline: none`을 쓰면 키보드 사용자가 자기 위치를 잃는다.
디자인상 기본 링이 안 맞으면 **대체 표시를 반드시 함께** 넣는다.

### 2. 키보드로 전부 조작 가능해야 한다

- 모든 인터랙티브 요소가 Tab으로 닿아야 한다
- 모달은 포커스를 **가두고**(focus trap), 닫으면 **호출한 요소로 되돌린다**
- Esc로 닫힌다
- `div`에 `onClick`을 달지 않는다. `button`을 쓴다

> 위 세 가지(포커스 트랩·복귀·Esc)는 **`<dialog>`가 이미 해 준다.**
> 직접 구현하면 어딘가 빠진다 → [네이티브 플랫폼 우선](./08-native-platform.md)

### 3. 색만으로 정보를 전달하지 않는다

색각 이상 사용자에게는 빨강/초록이 구분되지 않는다.
상태는 **색 + 아이콘 + 텍스트** 세 겹으로 표시한다
([아이콘 매핑](./06-iconography.md)).

### 4. 의미에 맞는 요소를 쓴다

- 제목은 `h1`~`h6`. 크기 때문에 레벨을 건너뛰지 않는다
- 목록은 `ul`/`ol`
- 폼 요소에는 `label`을 연결한다 (placeholder는 레이블이 아니다)
- 랜드마크(`main`, `nav`, `header`)를 쓴다

### 5. 이미지에 대체 텍스트

- 의미 있는 이미지 → 내용을 서술하는 `alt`
- 장식용 → `alt=""`

### 6. 언어를 선언한다

`<html lang>`이 실제 콘텐츠 언어와 맞아야 한다. 스크린리더의 발음이 여기서 갈린다.
다국어를 도입하면 로케일에 따라 바뀌어야 한다
([i18n 전략](../../30-architecture/06-i18n-strategy.md)).

한 문서 안에 다른 언어가 섞이면 그 부분에 `lang`을 지정한다:

```html
<span lang="ko" translate="no">외국인등록증</span>
```

이건 konnect에서 자주 발생한다 — 한국어 원문 병기가 관례이기 때문이다.
`translate="no"`를 함께 붙이는 이유는
[네이티브 플랫폼 우선](./08-native-platform.md#konnect-고유-적용-translateno) 참고.

## 확인 방법

| 방법 | 무엇을 잡나 |
| --- | --- |
| 키보드만으로 화면 조작 | 포커스 순서, 트랩, 닿지 않는 요소 |
| 브라우저 확대 200% | 잘리는 레이아웃 |
| 스크린리더 (VoiceOver / NVDA) | 레이블 누락, 읽기 순서 |
| axe DevTools 등 자동 검사 | 대비, 랜드마크, 대체 텍스트 |

> 자동 검사는 문제의 일부만 잡는다. **키보드 조작 확인**이 비용 대비 가장 효과적이다.

- 스크린리더 테스트를 누가 언제 하는가 → 열린 질문

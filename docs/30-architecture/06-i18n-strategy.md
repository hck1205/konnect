# 다국어 전략

> 이 서비스에서 다국어는 **부가 기능이 아니라 존재 이유**에 가깝다
> ([문제 정의 P5](../00-overview/02-problem-statement.md)).

## 세 층위를 구분한다

섞어서 생각하면 설계가 무너진다.

| 층위 | 무엇 | 전략 |
| --- | --- | --- |
| **1. UI 문구** | 버튼, 라벨, 안내 | 번역 리소스로 관리. 언어 추가는 파일 추가 |
| **2. 사용자 콘텐츠** | 질문·답변·게시글 | **번역하지 않는다.** 작성 언어 그대로 |
| **3. 큐레이션 콘텐츠** | 가이드·체크리스트 | 언어별 **독립 문서** 또는 번역본 (열린 질문) |

## 1. UI 문구

- **영어가 기준(source of truth)** — [ADR-0003](../50-decisions/0003-english-first-multilingual.md)
- **출시 시점부터 다국어**다 — [ADR-0005](../50-decisions/0005-multilingual-from-day-one.md).
  `en`(기준) · `ko` · `zh` · `vi` 로 시작하고 구조는 추가에 열려 있다
- 문구는 사전(`FE/src/lib/i18n/messages/`)에만 둔다. 컴포넌트 안에 하드코딩 금지
- 없는 키는 **키 그대로** 화면에 뜬다. 빈 문자열이면 누락을 눈치채지 못한다

### 구현

`FE/src/lib/i18n/` — 라이브러리 없이 `Intl` 위에 얇은 계층을 얹었다.

| 부분 | 무엇이 하는가 |
| --- | --- |
| 복수형 | **`Intl.PluralRules`**. 영어는 카테고리 둘, 한국어는 하나, 아랍어는 여섯 |
| 숫자·통화 | `Intl.NumberFormat`. 베트남어 천 단위는 마침표(`1.234.567`) |
| 날짜 | `Intl.DateTimeFormat`. 값은 UTC ISO, 표시는 브라우저 시간대 |
| 목록 나열 | `Intl.ListFormat`. 쉼표 join 으로는 "and"·"및"이 빠진다 |
| 상대 시각 | `Intl.RelativeTimeFormat` |
| 보간·폴백 | 직접 구현(약 100줄, 테스트됨) |

라이브러리를 쓰지 않은 이유와 옮길 시점은 [ADR-0005](../50-decisions/0005-multilingual-from-day-one.md) 참고.

### 로케일 라우팅

**로케일은 URL 세그먼트**다: `/ko/questions/123`.

- 언어별 고유 URL 이 있어야 검색엔진이 언어별로 색인한다.
  쿠키 기반이면 같은 URL 이 사람마다 다른 언어를 보여줘 색인이 하나로 뭉개진다 —
  검색 유입이 주 채널인 이 서비스에서는 손해다
- 세그먼트가 없는 요청은 **`Accept-Language` 로 협상**해 307 리다이렉트한다.
  품질값(`q=`)을 존중하고 `zh-CN` 같은 지역 태그는 기본 태그로 떨어뜨린다
- `<html lang>` 과 `dir` 이 로케일에 따라 바뀐다

## 2. 사용자 콘텐츠

**자동 번역을 전면 도입하지 않는다.** 행정·법률 용어에서 오역은 곧 피해다
([리스크 정책](../10-domain/10-visa-immigration/03-content-and-risk-policy.md)).

대신:
- 글에 **작성 언어를 태깅**한다 (`lang:en`, `lang:ko`) → 필터 가능
- 번역이 필요하면 **사용자가 명시적으로 요청**하는 보조 기능으로 (원문 항상 병기)
- 번역 결과에는 "기계 번역이며 부정확할 수 있음" 표시

## 3. 한국어 원문 병기 패턴

이 서비스 특유의 요구다. 계약서·공고·행정 서류의 한국어 원문을 **그대로 보여줘야**
사용자가 실제 문서에서 그 글자를 찾을 수 있다.

```
Certificate of Alien Registration (외국인등록증)
```

- 고유명사·서식명·행정용어는 **영문 + 한국어 원문 병기**를 관례로 한다
- [용어집](../00-overview/05-glossary.md)이 이 대응표의 출처가 된다
- 복사 가능해야 한다 (사용자가 검색창에 붙여넣는다)

## 열린 질문

- **`zh`·`vi` 원어민 검수** — 현재 미검수다. 행정 용어 오역은 R1 영역에서 실제 피해가 된다.
  **출시 차단 조건이다**
- 가이드를 언어별 독립 문서로 둘 것인가, 번역본으로 연결할 것인가?
  독립 문서는 내용이 갈라지고, 번역본은 최신성 동기화가 어렵다
- 사용자 콘텐츠에 **작성 언어 태그**를 붙여 필터링할 것인가?
- 사전을 동적 import 로 분리할 시점 — "번들에서 사전이 눈에 띌 때"

# 안전과 신뢰

> 교류 기능의 **선결 조건**. 이 문서의 항목이 갖춰지기 전에는 사람을 연결하는 기능을 열지 않는다.

## 왜 특별히 중요한가

타깃 사용자는 **취약한 위치**에 있다:

- 언어가 불편해 사기·부당 대우를 인지하기 어렵다
- 현지 지원망(가족·친구)이 없다
- 체류자격이 걸려 있어 신고를 주저할 수 있다
- 도움을 받아야 하는 처지라 **호의를 가장한 접근**에 노출된다

즉 일반 커뮤니티보다 **피해 가능성이 높고 회복이 어렵다**. 안전을 기능이 아니라 전제로 둔다.

## 위협 유형

| 유형 | 예 |
| --- | --- |
| 금전 사기 | 허위 매물, 보증금 사기, 대행 수수료 편취 |
| 브로커 | 비자·서류 대행을 빙자한 불법 알선 |
| 개인정보 수집 | 여권·ARC 사본 요구 |
| 괴롭힘·차별 | 국적·인종 기반 혐오 → **국적을 상시 노출하지 않는 이유** ([ADR-0009](../../50-decisions/0009-nationality-display-policy.md)) |
| 신체적 위험 | 오프라인 만남 |
| 스팸·광고 | 학원·부동산 영업 |

## 대응 장치

1. **신고 버튼을 모든 콘텐츠와 프로필에** 둔다 — 예외 없이
   ([모더레이션 기능](../../20-product/10-features/07-moderation-and-reporting.md))
2. **차단** — 차단한 사용자의 콘텐츠가 안 보이고, 밋업에서 마주치지 않게 한다
3. **신뢰 신호** — 계정 나이, 활동 이력, 평판. *신원 인증은 아니다*
4. **안전 가이드** — 밋업 페이지에 상시 노출(공개 장소, 개인정보 요구 거절, 금전 거래 금지)
5. **금전 거래 금지 정책** — 서비스 안에서 돈이 오가지 않게 한다. 위반 시 제재
6. **개인정보 게시 차단** — 여권/ARC/주소 게시를 금지하고, 작성 시점에 경고

## 신원 인증에 대한 입장

강한 신원 인증(여권 인증 등)은 신뢰를 크게 올리지만:

- 민감정보를 우리가 **보관**하게 된다 (리스크 이전이지 제거가 아니다)
- 가입 마찰이 커져 초기 성장에 치명적이다

→ **초기에는 하지 않는다.** 대신 행동 기반 신뢰 신호(3번)로 간다.

## 열린 질문

- 모더레이션을 누가 하는가? 자원봉사 모더레이터를 둘 것인가?
- 신고 처리 SLA를 어떻게 잡을 것인가? (안전 관련 신고는 별도 트랙이 필요)

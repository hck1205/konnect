# 체류자격 범위와 태그 체계

## 우리가 다루는 범위

전체 체류자격을 망라하지 않는다. [타깃 세그먼트](../../00-overview/03-target-users.md)에 대응하는 것부터 덮는다.

| 우선순위 | 체류자격 | 세그먼트 | 비고 |
| --- | --- | --- | --- |
| **1** | **F-5 (영주)** | **A** | **비치헤드.** 요건·서류·심사 질문이 핵심 |
| **1** | **F-2 (거주)** | **A** | 점수제(F-2-7) 계산이 최대 수요 |
| **1** | **귀화 / 국적** | **A** | 필기·면접. 체류자격은 아니지만 같은 관문이다 |
| **1** | E-7 (특정활동) | B | 정주 경로의 출발점. 스폰서·이직 이슈 |
| 2 | F-6 (결혼이민) | C | **민감도 최고** — [리스크 정책](./03-content-and-risk-policy.md) 필수 |
| 2 | D-10 (구직) | D | D-2 → D-10 → E-7 → F-2 경로 |
| 2 | F-4 (재외동포) | E | F-5 전환 수요가 있다 |
| 3 | E-2 (회화지도) | B | 특정 국적 집중 |
| 3 | H-1 (관광취업) | — | 국가별 협정 상이. 정주 의도 낮음 |
| 후순위 | D-2 / D-4 (유학·연수) | G → D | **재학 중은 비타깃.** 졸업 후 잔류 시점에 다룬다 |
| 후순위 | E-9 / H-2 (비전문취업) | F | 문제는 크나 [도달 수단이 없다](../../20-product/20-prd/02-segments-and-priority.md) |

**우선순위가 뒤집혔다.** 이전 판에서는 D-2(유학)가 1순위였다.
[ADR-0007](../../50-decisions/0007-settlement-intent-as-primary-axis.md) 로
축이 정주 의도로 바뀌면서 **F-2/F-5/귀화가 1순위**가 됐다.

## 태그 네임스페이스

질문·가이드에 붙는 맥락 태그는 **네임스페이스:값** 형태로 고정한다.
자유 태그와 섞이지 않게 하는 것이 목적이다 (→ [태그 설계](../../20-product/10-features/05-search-and-tagging.md)).

```
visa:d-2         visa:d-4        visa:e-7       visa:d-10
visa:f-2         visa:f-5        visa:f-6       visa:naturalization
region:seoul     region:busan    region:gyeonggi
school:snu       school:yonsei   ...
```

### 규칙

- 체류자격 태그 값은 **소문자 하이픈** 표기(`d-2`)로 정규화한다. 표시할 때만 `D-2`로 올린다.
- 하나의 글에 체류자격 태그를 **복수** 붙일 수 있다(전환 질문: `visa:e-7` + `visa:f-2`).
- 태그 목록은 **관리자가 관리하는 고정 어휘**다. 사용자가 새 체류자격 태그를 만들지 못한다
  (오탈자·유사어가 생기면 매칭이 무너진다).

## 열린 질문

- 체류자격 태그를 **필수**로 할 것인가? (강제하면 이탈, 안 하면 매칭 품질 하락)
- 프로필에 자기 체류자격을 저장해 두고 **자동 제안**할 것인가? 민감정보 취급 문제가 생긴다.

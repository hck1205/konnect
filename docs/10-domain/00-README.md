# 10 · 도메인

사용자가 **실제로 겪는 이슈 영역**. 제품 기능이 아니라 *문제*를 기준으로 나눈다.
각 영역은 나중에 `Topic`(주제 분류)과 태그 네임스페이스로 그대로 이어진다.

| 번호 | 영역 | 대표 질문 | 세그먼트 |
| --- | --- | --- | --- |
| 10 | [비자·체류](./10-visa-immigration/) | "F-2 점수가 되나?" | 전 세그먼트 (**A 비치헤드**) |
| 20 | [어학](./20-language/) | "KIIP 을 마치면 몇 점인가?" | A, C |
| 30 | [학교·교육](./30-education/) | "아이를 어느 학교에 보내나?" | C (자녀) · D (본인) |
| 40 | [주거·생활 행정](./40-housing-living/) | "보증금 떼이지 않으려면?" | 전 세그먼트 |
| 50 | [취업·커리어](./50-work-career/) | "이직하면 체류 기간이 초기화되나?" | B, D |
| 60 | [교류·커뮤니티](./60-social-community/) | "친구를 어떻게 만드나?" | 전 세그먼트 |

## 왜 이렇게 나눴나

- **선행조건으로 엮인 순서**를 반영한다: 비자 → ARC → 주거/통장/통신 → 학교/직장 → 사회생활 → **영주·귀화**.
  이 의존 관계가 [체크리스트 기능](../20-product/10-features/)의 근거다.
- 영역마다 **정보의 성격이 다르다**. 비자는 규정 기반(정확성이 생명),
  교류는 경험 기반(정확성보다 매칭). 그래서 영역별로 콘텐츠 정책이 달라진다.

## 공통 규칙

- 규정이 걸린 영역(10·30·50)의 문서는 반드시
  [콘텐츠·리스크 정책](./10-visa-immigration/03-content-and-risk-policy.md)을 따른다.
- 각 영역 문서는 **절차를 그대로 옮겨 적지 않는다.** 우리 서비스가 그 영역에서
  *무엇을 다루고 무엇을 다루지 않는지*를 정의하는 것이 목적이다.

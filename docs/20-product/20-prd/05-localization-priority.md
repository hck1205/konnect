# 05 · 지원 언어의 순서와 기준

현재 지원: **`en`(기준) · `ko` · `zh` · `vi`** ([ADR-0005](../../50-decisions/0005-multilingual-from-day-one.md))

> 타깃이 **정주 의도**로 바뀌면서 이 문서의 결론이 바뀌었다
> ([ADR-0007](../../50-decisions/0007-settlement-intent-as-primary-axis.md)).
> 특히 **`ko` 의 역할이 커지고, 언어 확장의 긴급도가 낮아진다.**

## 언어 하나의 진짜 비용

"사전 파일 하나 추가"가 아니다.

| 비용 | 내용 |
| --- | --- |
| 초기 번역 | 사전 전체 |
| **지속 검수** | 화면이 늘 때마다 **모든 언어**가 늘어난다 |
| **행정 용어 정확도** | R1 영역. 오역이 실제 피해 — **원어민 검수가 출시 차단 조건** |
| 빈 콘텐츠 | UI 만 번역되고 **질문·답변이 그 언어로 없으면** 첫 화면이 텅 빈다 |

**마지막이 가장 무섭다.** UI 번역은 쉽고 콘텐츠는 어렵다.
언어를 늘리는 것보다 **그 언어 사용자가 그 언어로 글을 쓰게 만드는 것**이 본체다.

→ 언어 추가는 **세그먼트 진입과 함께**만 한다. UI 만 먼저 늘리지 않는다.

## 정주 타깃에서 달라지는 것

### 1. 정주자는 한국어를 한다

비치헤드인 **영주·귀화 준비자는 체류 5년차 이상**이다. 그리고
[사회통합프로그램(KIIP)과 TOPIK 이 영주·귀화의 실질 요건](./03-interests-and-jobs.md)이라
**한국어를 공부해야만 하는 사람들**이다.

즉 이 집단은 **한국어로 검색하고 한국어로 물을 수 있다.**

- `ko` 는 더 이상 "한국인 도우미용"이 아니다. **타깃 본인의 언어**다
- 한국어 원문 병기의 가치가 더 커진다 — 원문을 읽을 수 있는 사용자들이다

### 2. 언어 확장의 긴급도가 낮아졌다

유학생 타깃에서는 언어가 곧 진입 장벽이었다(입국 1년차, 한국어 못 함).
정주 타깃에서는 **`ko` + `en` + `vi` 만으로 비치헤드를 덮을 수 있다.**

**언어 확장은 C(결혼이민)로 확장할 때 급해진다.** 그전까지는 자원을
언어 추가가 아니라 **콘텐츠와 검수**에 쓴다.

## 선정 기준

1. **정주 지향** — 그 언어권이 눌러앉는가, 잠깐 왔다 가는가
2. **대체 언어 없음** — 영어나 한국어로 이미 되는 집단은 후순위
3. **세그먼트 진입 시점** — P0·P1 과 겹치는가
4. **언어 통합 효과** — 여러 국적을 하나로 묶는가

## 현재 4개 언어의 근거

| 언어 | 근거 | 정주 축에서 |
| --- | --- | --- |
| `ko` | 원문 병기의 기준 · 한국인 도우미 | **격상.** 정주자 본인의 언어다 |
| `en` | **공통 언어.** 나머지를 묶는 최소공통분모 | 유지. B(정착 취업자)의 주 언어 |
| `vi` | 베트남 337,183 (2위) · **신규 국제결혼 32.1% (1위, 3년 연속)** | **유지 — 여전히 1순위 확장 언어** |
| `zh` | 중국 980,670 (1위) · **누적 결혼이민 1위** | 유지. 단 아래 참고 |

### `zh` 는 모수 1위지만 실효 모수는 그보다 작다

중국 국적 980,670명 중 상당수가 **한국계중국인(조선족)** 이다
(F-4 재외동포 556,208명이 대리 지표). **한국어에 불편이 없다.**

`zh` 를 뺄 이유는 아니다 — 누적 결혼이민자 중 중국이 1위이고, 한국어가 안 되는
중국 국적자도 많다. 다만 **`vi` 와 `zh` 에 같은 자원을 쓰는 것은 잘못된 배분**이다.

### 이전 판단을 두 개 뒤집는다

| | 이전 (유학 축) | 지금 (정주 축) | 왜 |
| --- | --- | --- | --- |
| `th` | 4순위 — "감소 중(−10%), 미등록 비중 높아 도달 낮음" | **1순위** | 감소하는 건 **노동 세그먼트**다. 결혼이민 태국인은 등록돼 있고 **눌러앉는다** — 완전히 다른 집단이다 |
| `ja` | **"넣지 않는다 — 근거 없음"** | **2순위** | 유학·노동에서는 근거가 없었다. **정주에서는 신규 7.5% · 누적 8.9%** 로 명확한 근거가 생겼다 |

`ru` 는 **하향**한다. 통합 효과는 여전히 크지만 우즈벡·카자흐는 유학·노동 중심이라
정주 축에서 앞자리를 줄 근거가 약하다. E(동포) 진입 시점에 다시 본다.

## 영어를 기준 언어로 유지하는 이유

`vi` 사용자가 더 많은데도 기준은 `en` 이다.

- **폴백 대상**이 필요하다. 번역이 없을 때 떨어질 곳이 하나 있어야 한다
- 필리핀을 포함해 **나머지 국적을 묶는 유일한 언어**다
- B(정착 취업자)의 주 언어다
- 개발·문서·용어의 기준이 하나여야 한다

**기준 언어 ≠ 1순위 투자 대상.** 검수·콘텐츠 투자는 `ko`·`vi` 가 먼저다.

## 구현이 이미 준비한 것

언어 추가가 **파일 추가로 끝나도록** 되어 있다:

- 복수형은 `Intl.PluralRules` — 언어별 규칙을 우리가 갖고 있지 않다
- 숫자·날짜·목록도 `Intl` (베트남어 천 단위는 마침표: `1.234.567`)
- 누락 키는 **키 그대로 화면에 뜬다** — 빈 문자열이면 못 본다
- `messages.test.ts` 가 사전 간 키 정합성을 검사한다

**새 사전이 이 테스트를 통과하는 것은 최소 조건이고, 충분조건이 아니다.**
충분조건은 **원어민 검수**다.

## 사용자 콘텐츠의 언어

UI 언어와 **글의 언어는 다른 문제**다.

- 사용자 글은 **번역하지 않는다** ([ADR-0003](../../50-decisions/0003-english-first-multilingual.md))
- 대신 **작성 언어 태그**를 붙이고 피드에서 필터한다 ([S7](./04-requirements.md))
- 이유: 한 언어의 글이 다른 언어 피드를 덮으면 **양쪽 사용자를 다 잃는다**

**정주 타깃에서는 이 문제가 완화된다** — 한국어를 공유하는 사용자가 많아
`ko` 가 사실상 공통 피드 역할을 할 수 있다.

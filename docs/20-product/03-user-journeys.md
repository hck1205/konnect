# 사용자 여정

## J1 · 검색으로 들어온 첫 방문자 (가장 중요)

```
Google "F-2-7 points volunteer work korea"
  → konnect 질문 상세 페이지 착지
  → 답을 읽음 (로그인 없이)
  → 관련 글 / 같은 태그 글로 이동
  → [전환점] 자기 상황이 조금 달라 질문하고 싶다 / 나중에 다시 보고 싶다
  → **저장·구독은 로그인 없이** (마이크로 전환)
  → 로그인 (OAuth) — "저장한 것을 잃지 않으려면"
  → 질문 작성 (태그 자동 제안)
```

**설계 함의**
- 상세 페이지는 **로그인 없이 완전히 읽혀야** 한다
- 상세 페이지 하단의 "관련 글"이 체류 시간을 만든다
- 로그인은 **작성 시점에만** 요구한다 (읽기 전에 벽을 세우지 않는다)
- 질문 작성 시 태그를 **자동 제안**한다 (본문에서 `F-2` 감지 → `visa:f-2` 제안)

## J2 · 답변자 (커뮤니티를 굴리는 사람)

```
알림: "내 관심 태그에 새 질문"
  → 질문 확인 → 답변 작성
  → 채택됨 → 프로필에 기록
  → 다시 방문
```

**설계 함의**
- **관심 태그 구독**이 답변자를 데려오는 유일한 장치다 (P1 알림의 핵심 용도)
- 채택·감사 표시가 유일한 보상 — 눈에 보여야 한다

## J3 · 준비 중인 사용자 — **리텐션 엔진**

```
"내 점수가 되나" (막연함)
  → 온보딩 3문항 (비자 · 연차 · 지역)
  → /me : F-2 점수 77/80 · ARC 만료 D-127
  → 모자란 항목에서 질문/가이드로 이동
  → 몇 주 뒤 **상태가 바뀌었는지 보러 다시 온다**
```

**설계 함의**
- **이 서비스의 리텐션은 피드가 아니라 진행 상태에서 나온다.**
  글이 적고, 유입이 상세 페이지이고, 정주자는 매일 올 이유가 없다 —
  다시 오게 하는 것은 **시간이 흐르는 내 상태**다
- 체크리스트가 **가이드와 질문의 허브**가 된다
- 입력값은 **민감정보다.** 계산은 클라이언트에서 하고 저장하지 않는다
  ([07-monetization](./20-prd/07-monetization.md#최대-기회이자-최대-리스크--요건-계산기))

## J4 · 고립된 사용자

```
정보는 다 찾았는데 아는 사람이 없다
  → 밋업 목록 (지역 필터)
  → 참가 신청 → 참여
  → 다시 방문
```

**설계 함의** — [안전과 신뢰](../10-domain/60-social-community/02-safety-and-trust.md)가 선결

## 여정별 우선순위

**J1 > J3 > J2 > J4.**

- **J1 이 유입**을 만든다 — 검색이 유일한 채널이다
- **J3 이 리텐션**을 만든다 — 예전에는 J2(답변자) 다음이었는데,
  타깃이 [정주 의도](../50-decisions/0007-settlement-intent-as-primary-axis.md)로 바뀌면서
  **진행 상태가 재방문의 주된 이유**가 됐다
- **J2 가 공급**을 만든다 — J3 를 지나온 사람이 J2 가 된다. 순서가 이렇게 된다
- J4 는 [안전 장치와 인력이 전제](../50-decisions/0004-direct-messages-with-safety-gates.md)라 Phase 3 이다

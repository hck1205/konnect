# 성공 지표

## 원칙

- 단계마다 **하나의 핵심 질문**이 있고, 지표는 그 답이다 ([릴리스 단계](./04-mvp-scope.md)).
- 허영 지표(누적 가입자, 총 PV)를 목표로 삼지 않는다.
- **초기에는 숫자보다 인터뷰**다. 사용자가 적을 때 비율 지표는 노이즈다.

## M1 — "검색으로 들어온 사람이 답을 찾는가?"

| 지표 | 정의 | 왜 |
| --- | --- | --- |
| **답변된 질문 비율** | 답변 ≥1인 질문 / 전체 질문 | 이게 낮으면 커뮤니티가 아니다 |
| **첫 답변까지 시간** | 중앙값 | 물어볼 만한 곳인지의 체감 |
| 검색 유입 비율 | 오가닉 검색 세션 / 전체 | 유입 가설 검증 |
| 상세 페이지 이탈률 | 착지 후 바로 이탈 | 답이 쓸모 있었는가 |

## M2 — "답변자가 다시 오는가?"

| 지표 | 정의 |
| --- | --- |
| **답변자 재방문율** | 답변 후 7일 내 재방문 |
| 답변자 수 / 질문자 수 | 공급-수요 균형 |
| 태그 구독 → 답변 전환율 | 알림이 실제로 작동하는가 |

## M3 — "초기 정착 문제가 풀리는가?"

| 지표 | 정의 |
| --- | --- |
| 체크리스트 완료율 | 시작한 사람 중 끝까지 간 비율 |
| 가이드 편집 참여자 수 | 축적이 자생하는가 |
| 콘텐츠 최신성 | 6개월 내 확인된 R1 문서 비율 |

## M4 — "사람이 연결되는가?"

| 지표 | 정의 |
| --- | --- |
| 밋업 성사율 | 등록된 밋업 중 실제 진행 |
| 재참가율 | 두 번 이상 참가 |
| **신고 처리 시간** | 안전 지표 — 이건 상한을 넘으면 안 되는 종류다 |

## 보지 않을 것

- 누적 가입자 수 — 활동하지 않는 계정은 아무것도 말해주지 않는다
- 총 게시글 수 — 스팸으로도 오른다
- 체류 시간 — 답을 빨리 찾을수록 짧아진다. 이 서비스에선 **낮은 게 좋을 수도** 있다

## 열린 질문

- 분석 도구를 무엇으로 할 것인가? 개인정보 최소 수집 원칙과 충돌하지 않아야 한다
- 타깃이 민감한 정보를 다루므로, **어떤 이벤트를 수집하지 않을지**를 먼저 정해야 한다

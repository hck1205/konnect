# 알림

> 우선순위 **P1** · 답변자를 데려오는 유일한 장치

## 왜 필요한가

[J2(답변자 여정)](../03-user-journeys.md)는 알림 없이 성립하지 않는다.
답변자는 질문을 찾아다니지 않는다 — 자기 관심사에 질문이 생겼을 때 알려줘야 온다.

## 이벤트

| 이벤트 | 대상 | 우선순위 |
| --- | --- | --- |
| 내 질문에 답변이 달림 | 질문자 | 1 |
| **구독한 태그에 새 질문** | 구독자 | 1 — 공급을 만든다 |
| 내 답변이 채택됨 | 답변자 | 2 |
| 내 글에 댓글 | 작성자 | 2 |
| 멘션됨 | 대상자 | 3 |
| 신고 처리 결과 | 신고자/작성자 | 3 |

## 채널

| 채널 | 시점 |
| --- | --- |
| 인앱 (벨 아이콘) | MVP 직후 |
| 이메일 | 선택 — 재방문에 가장 효과적이지만 스팸이 되기 쉽다 |
| 푸시 | 앱이 생기면 (현재 비범위) |

## 원칙

- **기본값은 최소한.** 알림 피로가 오면 전부 끈다
- 묶어서 보낸다 (같은 글의 답변 3개 → 알림 1개)
- 이메일은 **명시적 동의** 후에만
- 구독 태그 알림은 **빈도 상한**을 둔다 (인기 태그는 하루 수십 건이 될 수 있다)

## 열린 질문

- 이메일 알림을 MVP 직후에 넣을 것인가? 재방문 효과는 크지만 발송 인프라와 스팸 정책이 필요하다
- 실시간(SSE)이 필요한가, 폴링으로 충분한가? → 초기에는 폴링으로 충분해 보인다

# 공식 데이터 파이프라인 — 긁어오고, 정제하고, 제공한다

> [11-official-sources](./11-official-sources.md) 는 **"바뀌었나"** 를 답한다(감시).
> 이 문서는 **"무엇을 실을 수 있나"** 를 답한다(수집·정제·제공).
>
> 둘을 나눈 이유: 감시는 해시만 있으면 되지만, 화면에 내보내려면 **원문·인용 등급·
> 저장 위치·정제 규칙**이 전부 필요하다. 같은 문서에 두면 "감시가 되니 표시도 된다"는
> 착각이 생긴다 — 실제로는 감시 데이터가 앱에 닿지도 않는다(아래 "지금 막혀 있는 것").

## 왜 이 파이프라인이 제품의 핵심인가

이 서비스에는 **전문가가 없다.** 그래서 비자 요건을 우리가 쓸 수 없다
([R1 정책](../../10-domain/10-visa-immigration/03-content-and-risk-policy.md)).

그런데 **쓰지 않고 인용하는 것은 할 수 있다.** 법령·고시는
[저작권법 제7조](https://casenote.kr/법령/저작권법/제7조)상 보호받지 못하는 저작물이라
전문 인용이 가능하다. 즉 이 파이프라인은 **전문가 없이 핵심 정보를 제공하는 유일한 길**이다.

그리고 사용자가 0명이어도 성립한다 — 다른 모든 페이지 종류가 볼륨 조건에 걸리는 것과 다르다.

| 페이지 종류 | 성립 조건 |
| --- | --- |
| 태그 허브 | 질문 20건 + 답변률 평균 이상 |
| 공간 승격 | 주간 신규 10건 × 4주 |
| 회사 페이지 | 사용자가 경험을 써야 채워진다 |
| **공식 출처 페이지** | **없다 — 원본이 존재하면 성립한다** |

## 원본이 실제로 무엇을 주는가

⚠️ **아래는 추정이 아니라 2026-08-31 A1 서버에서 실측한 결과다.**
법제처 API 는 [호출 IP 를 사전 등록](./11-official-sources.md)해야 해서
로컬에서는 재현되지 않는다.

### 법령 API — `target=law`

```
GET https://www.law.go.kr/DRF/lawService.do?OC=<키>&target=law&type=JSON&LM=<법령명>
```

출입국관리법 시행령 응답 **366KB**, 최상위 키는 `법령` 하나.

```
법령
├ 기본정보      법령명_한글 · 시행일자 · 공포일자 · 소관부처 · 제개정구분
├ 조문          (본문)
├ 별표          별표단위[]        ← 여기가 핵심이다
├ 부칙
└ 개정문
```

**`별표단위` 에 본문 텍스트가 그대로 들어 있다.** 링크만 주는 게 아니다.

| 별표 | 제목 | 무엇인가 |
| --- | --- | --- |
| 1 | 단기체류자격 | B-2, K-ETA 등 |
| **1의2** | **장기체류자격** | **D-2·E-7·F-2 … 모든 장기 체류자격의 정의** |
| **1의3** | **영주자격에 부합하는 사람** | **F-5 요건** |
| 2 | 과태료의 부과기준 | |

별표1의2 의 `별표내용` 은 **26,215자**였다. PDF·HWP·이미지 링크도 따로 온다
(`별표서식PDF파일링크` 등) — 표가 이미지로 된 부분이 있어 **텍스트만으로 완결되지 않는
경우가 있다.** 이것이 정제 단계에서 판단해야 할 지점이다.

### 행정규칙 API — `target=admrul`

```
GET .../lawSearch.do?OC=<키>&target=admrul&type=JSON&query=<검색어>   ← 검색
GET .../lawService.do?OC=<키>&target=admrul&type=JSON&ID=<행정규칙ID> ← 본문
```

응답 루트가 법령과 **다르다**: `AdmRulSearch.admrul[]` (법령은 `LawSearch.law[]`).
본문 응답의 구조도 다르다 — `조문내용 · 별표 · 행정규칙기본정보 · 첨부파일 · 부칙 · 제개정이유`.

**같은 파서를 쓸 수 없다.** 이것이 정제 계층이 필요한 첫 번째 이유다.

찾아낸 것 — `query=체류자격`, 법무부 현행 4건:

| 행정규칙 | 종류 | 발령 |
| --- | --- | --- |
| **출입국관리법시행령 별표 1의2 중 24. 거주(F-2)자목에 해당하는 자의 연령·학력·소득 등에 관한 고시** | **고시** | 2025-10-24 |
| 시행령 별표 1의2 제24호 거주(F-2) '차'목 부동산 투자지역 고시 | 고시 | 2026-02-11 |
| 공익사업 투자이민제도 투자대상·투자금액 기준 고시 | 고시 | 2023-06-29 |
| 각종 체류허가 등의 신청 및 수령의 대리에 관한 규정 | 고시 | 2020-12-09 |

첫 번째가 **F-2-7 점수제**다(`자`목 = F-2-7). 우리 비치헤드의 최대 수요이고,
고시라 **전문 인용이 가능하다.**

### ❌ E-7 직종은 법제처에 없다

리크루트 축의 전제가 여기서 바뀐다. 네 가지로 검색했고 **전부 법무부 현행 0건**이었다:

```
특정활동(E-7)   0건
외국인력 도입    0건
직종            0건
고용추천        0건
```

E-7 직종 목록은 고시가 아니라 법무부 **「사증발급 안내매뉴얼」·「외국인체류 안내매뉴얼」**
에 있다. 매뉴얼은 저작권법 제7조 대상이 **아니다** —
[인용 범위](./11-official-sources.md#인용-범위--저작권)의 "기관 안내문" 등급이라
**링크 + 최소 인용만** 가능하다.

| | 인용 등급 | 리크루트 축에서 |
| --- | --- | --- |
| 시행령 별표1의2 (E-7 정의) | **전문 인용 가능** | E-7 이 무엇인지는 실을 수 있다 |
| E-7 **직종 목록** (매뉴얼) | 링크 + 최소 인용 | **"내 직무가 되나"의 답은 실을 수 없다** |

**그래서 리크루트 정보는 비자 정보와 같은 깊이로 못 간다.** 같은 파이프라인을 쓰되
결과물의 성격이 다르다는 것을 전제하고 설계해야 한다.

## ⚠️ 응답에 인증키가 박혀서 온다

실측 중 발견했다. 법제처가 돌려주는 링크 필드에 **요청에 쓴 `OC` 값(=인증키)이 그대로
들어 있다.**

```json
"행정규칙상세링크": "/DRF/lawService.do?OC=<우리 키>&target=admrul&ID=...&type=HTML"
"법령상세링크":     "/DRF/lawService.do?OC=<우리 키>&target=law&MST=...&type=HTML"
```

**원본 응답을 그대로 저장하거나 화면에 내보내면 키가 함께 나간다.**
정제 단계에서 반드시 제거하거나 공개용 URL(`https://www.law.go.kr/법령/...`)로 바꿔야 한다.

이 키는 IP 에 묶여 있어 단독 가치는 낮지만, 그것이 노출을 허용할 이유는 아니다.
[env-chmod 원칙](./11-official-sources.md)과 같다 — **노출된 비밀은 값을 바꾸는 것 말고
되돌릴 방법이 없다.**

## 지금 막혀 있는 것 — 앱이 이 데이터를 읽을 수 없다

감시는 상태를 named volume 에 쓰는데, 그 볼륨이 **감시 컨테이너에만** 붙어 있다.

```yaml
watch-sources:
  volumes: [konnect-source-state:/app/var]   # 여기만
konnect-be:
  # 볼륨 없음 → 화면에 띄울 방법이 없다
```

수집은 되는데 제공이 안 되는 상태다. 두 가지 길이 있다.

| | 볼륨을 BE 에 읽기 전용 마운트 | **Postgres 에 쓴다 (권장)** |
| --- | --- | --- |
| 비용 | 싸다 | 스키마·마이그레이션 필요 |
| 질문과 조인 | **안 된다** | 된다 — "이 출처를 참조하는 질문 7건" |
| 백업 | 볼륨은 백업 대상 밖 | 기존 pg 백업에 포함 |
| 이력 | 파일 하나에 30건 상한 | 행으로 쌓인다 |

**Postgres 를 권한다.** 출처 페이지의 설계에 "이 출처를 참조하는 질문 N건"이 이미
들어 있는데, 그건 조인 없이는 만들 수 없다.

다만 감시 컨테이너가 DB 에 붙으면 **네트워크 격리가 깨진다** — 지금 `watch-egress` 에
따로 둔 이유가 "DB 를 안 쓰니까"였다. 붙이려면 `core-network` 로 옮겨야 하고,
그건 이 박스의 다른 앱 DB 에도 닿는다는 뜻이다. **격리를 포기하는 대가를 알고 결정해야 한다.**

## 파이프라인 단계

```
① 수집    법제처 API · 페이지 폴링          레지스트리(BE/data/official-sources.json)가 대상을 정한다
   ↓
② 정제    키 제거 · 소스별 파서 · 인용 등급 부여   ← 여기가 이 문서의 이유다
   ↓
③ 저장    Postgres                          변경 이력이 행으로 쌓인다
   ↓
④ 감시    해시 비교 → 변경 시 이슈           이미 동작 중 (cron 09:00 KST)
   ↓
⑤ 제공    /[locale]/visa/[code] 등           해석 없이 인용·링크·날짜만
```

**②가 없으면 ③~⑤가 전부 하드코딩이 된다.** 소스마다 응답 구조가 다르고
(`법령` vs `AdmRulSearch`), 인용 등급이 다르고, 키가 섞여 온다.

### 정제가 반드시 하는 것

1. **인증키 제거** — 위 참조
2. **소스 종류별 파싱** — `target=law` 와 `target=admrul` 은 구조가 다르다
3. **인용 등급 부여** — 전문 인용 가능 / 링크+최소 인용 / 출처 표기 후 인용
4. **이미지 의존 표시** — 별표에 표가 이미지로 들어 있으면 텍스트만으로 불완전하다.
   그 사실을 화면이 알아야 "원문 보기"를 강조할 수 있다
5. **공개 URL 생성** — 내부 API 링크가 아니라 사람이 열 수 있는 주소

## 열린 질문

- **이미지로 된 표를 어떻게 다루나?** 별표1의2 에 `.gif` 참조가 여럿 있다.
  OCR 은 R1 영역에서 위험하다 — 잘못 읽으면 틀린 요건을 만든다. 지금 답은 "원문 링크로 보낸다"
- **E-7 직종을 어디서 가져오나?** 법제처에 없다. 하이코리아 매뉴얼을 폴링하면
  인용 등급이 낮아 링크만 남는다. 그것으로 리크루트 축이 성립하는가
- **감시 컨테이너를 DB 에 붙이면서 격리를 어디까지 포기할 것인가**
- 법제처 API 의 이용 조건(호출 빈도·재배포)을 확인하지 않았다. 하루 1회라 문제가 없어
  보이지만 **확인한 적은 없다**

# 1:1 쪽지

> 우선순위 **P2** · **안전 장치가 출시 조건이다**
> → [ADR-0004](../../50-decisions/0004-direct-messages-with-safety-gates.md)

## 목적

공개할 수 없는 개인 상황을 다룰 통로.

공개 댓글에 회사명·학교·체류자격 세부를 쓸 수 없다. 그건 공개하면 안 되는 정보인데,
그것 없이는 답할 수 없는 질문이 있다.

## 왜 이게 위험한 기능인가

타깃 사용자는 **취약한 위치**에 있다
([안전과 신뢰](../../10-domain/60-social-community/02-safety-and-trust.md)):

- 언어가 불편해 사기·부당 대우를 인지하기 어렵다
- 현지 지원망(가족·친구)이 없다
- 체류자격이 걸려 있어 신고를 주저한다
- 도움을 받아야 하는 처지라 **호의를 가장한 접근**에 노출된다

그리고 공개 글과 결정적으로 다른 점: **커뮤니티가 자정할 수 없다.**
아무도 볼 수 없는 곳에서 일어나기 때문이다.

## 출시 조건 (전부 필수)

| # | 장치 | 왜 |
| --- | --- | --- |
| 1 | 안전 고지 **상시 노출·닫기 불가** | 사기가 가장 자주 시작되는 경로다 |
| 2 | 차단·신고를 **한 번의 조작**으로 | 메뉴 깊숙이 두면 위급한 순간에 못 찾는다 |
| 3 | 민감정보 형태 **경고** | 여권번호·13자리 번호. **막지는 않는다**(오탐이 잦으면 무시하게 된다) |
| 4 | 수신 거부 설정 | 쪽지를 아예 받지 않을 수 있어야 한다 |
| 5 | 신고 **긴급 트랙** | 쪽지 신고는 사기·개인정보 트랙으로 |
| 6 | 금전 거래 금지 정책 | 위반 시 제재 |
| 7 | **신고 처리 인력** | 이게 없으면 나머지 여섯이 무의미하다 |

7번이 기술이 아니라 **운영**이라는 점이 핵심이다. 그래서 이 기능은
[MVP 에서 빠져 있다](../04-mvp-scope.md) — 컴포넌트는 만들어 두었지만 화면에 붙이지 않는다.

## 하지 않는 것

| 항목 | 이유 |
| --- | --- |
| 실시간 채팅(WebSocket) | 즉답 압박이 사기 수법의 효과를 키운다. **비동기**가 이 서비스에 맞다 |
| 첨부 파일 | 서류 사진을 주고받는 순간 위험이 몇 배가 된다 |
| 그룹 대화 | 1:1 만. 그룹은 공개 게시판이 있다 |
| 메시지 수정 | 상대가 읽은 뒤 내용이 바뀌면 분쟁이 생긴다 |

## 모델 (초안)

```
Conversation
  id, participantIds[2]        1:1 이므로 정확히 둘
  lastMessageAt                목록 정렬용
ConversationState              참가자별 상태 — 한 대화에 두 개
  conversationId, userId
  unreadCount, lastReadAt, blocked, archived
Message
  id, conversationId, senderId, body, createdAt
  readAt?
```

`ConversationState` 를 분리한 이유: 안 읽음·차단은 **사람마다 다르다.**
Conversation 에 넣으면 한쪽의 차단이 양쪽에 적용된다.

## 열린 질문

- 모르는 사람에게 먼저 보내기에 조건(계정 나이·활동 이력)을 붙일 것인가?
- 대화 보존 기간 — 무기한이면 유출 시 피해가 커진다
- 차단하면 **기존 대화**를 어떻게 할 것인가? (숨김 vs 읽기 전용)

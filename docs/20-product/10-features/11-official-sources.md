# 공식 출처 감시

> **전문가가 없다.** 그래서 이 기능은 **해석하지 않는다** — 정확한 공식 문서로 데려갈 뿐이다.

## 무엇을 푸는가

정부 정보는 **존재하지만 찾을 수 없다.** 하이코리아에 F-2 안내가 있어도
"내 상황에 해당하나"를 알 수 없고, 시행령이 바뀌어도 **내 비자에 영향이 있는지** 아무도 안 알려준다.

konnect 는 그 사이를 잇는다. 다만 **답을 말하지 않는다** —
[우리는 답을 만들지 않고 답이 모이게 한다](../../00-overview/01-product-vision.md).

## 선: 전달과 해석

| | 하는 것 | 예 |
| --- | --- | --- |
| **전달** ✅ | 원문·링크·개정일을 **그대로** 보인다 | "시행령 별표1의2 · 2026-03-14 개정 · [원문]" |
| **해석** ❌ | 요약·번역·"당신 경우엔" | "F-2 는 이제 80점이 필요합니다" |

**해석을 자동 생성하지 않는 이유**는 검증할 사람이 없어서다.
[R1 영역](../../10-domain/10-visa-immigration/03-content-and-risk-policy.md)에서
틀린 요약은 신청 반려로 이어지고, **자동 생성은 그것을 대량으로 만든다.**

해석은 **사용자의 경험**이 채운다. 그게 Q&A 다.

## 인용 범위 — 저작권

| 대상 | 인용 | 근거 |
| --- | --- | --- |
| **법률·시행령·시행규칙·고시·공고·훈령** | **전문 인용 가능** | [저작권법 제7조](https://casenote.kr/법령/저작권법/제7조) — 보호받지 못하는 저작물 |
| 기관 안내문·해설 (하이코리아 안내 등) | **링크 + 최소 인용** | 법령이 아니라 저작물일 수 있다 |
| 통계·데이터 | 출처 표기 후 인용 | 이용 조건(KOGL 유형) 확인 |

**이 구분을 코드에 넣는다** — 출처 종류에 따라 저장·표시 방식이 다르다.

## 시스템 — 생성이 아니라 감시

```
① 출처 레지스트리        사람이 관리하는 목록 (BE/data/official-sources.json)
        │                visa:f-2 → 시행령 별표1의2 · 하이코리아 안내 · 공지사항
        ▼
② 주기 수집 (자동)        법제처 OPEN API · 페이지 해시
        │                하루 1회
        ▼
③ 변경 감지 (자동)        개정일 / 본문 해시 비교
        │
        ├─▶ ④ 출처 페이지 갱신 (자동)   /sources/visa/f-2 — 사실만
        └─▶ ⑤ 신선도 표시 (자동)        연결된 Q&A 에 "출처가 바뀜" 배지
```

**⑤가 이 기능의 진짜 값어치다.** 지금 신선도 배너는 *작성일*만 안다 —
"제도가 바뀌었는지"는 모른다. 출처 감시가 그걸 채운다.

## 자동 생성하는 페이지

해석이 없어 안전하고, **아무도 제공하지 않는** 정보다.

```
/[locale]/sources/visa/f-2

  F-2 (거주) — 공식 출처                    마지막 확인 2026-08-31

  출입국관리법 시행령 별표1의2               2026-03-14 개정   ⚠ 3개월 전 변경
  하이코리아 — 체류자격별 안내                2025-11-02 확인
  출입국·외국인정책본부 공지사항               관련 2건

  ── 변경 이력 ──
  2026-03-14  시행령 별표1의2 개정
  2025-11-02  안내 페이지 갱신

  ── 이 출처를 참조하는 질문 7건 ──
```

- **색인한다.** `F-2 요건 바뀌었나` 같은 검색에 대응한다
- **해석이 없다.** 링크·날짜·원문 인용뿐이다
- [허브 승격 기준](../../50-decisions/0011-taxonomy-that-scales.md)을 적용하지 않는다 —
  출처 페이지는 비자 자격 수(~15)만큼만 생긴다

## 수집 대상

| 출처 | 접근 | 비고 |
| --- | --- | --- |
| **법제처 OPEN API** (`law.go.kr/DRF`) | **API 키 + IP 등록 필요** (무료) | 법령 본문·개정일. `robots.txt` 전면 허용 |
| 출입국·외국인정책본부 공지사항 | 페이지 폴링 | `robots.txt` 가 일부 경로만 제한 — 공지 목록은 허용 |
| 하이코리아 안내 | 페이지 폴링 | 링크 위주. 본문 인용은 최소 |

### ⚠️ 법제처 API 는 **호출 IP 를 사전 등록**해야 한다

키만으로는 안 된다. 등록되지 않은 IP 에서 부르면 이렇게 온다(실측):

```json
{ "result": "사용자 정보 검증에 실패하였습니다.",
  "msg": "OPEN API 호출 시 정확한 서버장비의 IP주소 및 도메인주소를 등록해 주세요." }
```

**이 제약이 실행 위치를 결정한다.**

| | |
| --- | --- |
| GitHub Actions | ❌ **불가능** — 러너 IP 가 매번 바뀌고 대역이 수천 개다 |
| **A1 서버** | ✅ **고정 IP**. 한 번 등록으로 끝난다 → `deploy/a1-watch-sources.sh` |
| 개발 PC | ⚠️ 가능하나 **가정용 회선은 IP 가 바뀐다**. 바뀌면 재등록 |

`OC` 값은 **가입 이메일의 아이디 부분**이 관례다(직접 지정 가능).
[open.law.go.kr](https://open.law.go.kr) → OPEN API 신청 → API인증키관리.

키가 없으면 법령 3건은 건너뛰고 **페이지 감시는 계속 돈다** — 부분 동작이 가능하다.

**환경변수 이름은 `KONNECT_LAW_API_KEY`** 다. 운영 서버의 `.env` 는 한 박스의
여러 앱이 공유하므로 앱별 prefix 를 쓴다. prefix 없는 `LAW_API_KEY` 도 받지만
(로컬 편의) 둘 다 있으면 prefix 쪽이 이긴다.

⚠️ **이름이 어긋나면 실패가 아니라 "건너뜀"으로 보인다.** 그래서 시작할 때
어느 변수를 썼는지 로그에 남긴다 — `법령 API 키: KONNECT_LAW_API_KEY 사용`.

## 예의 — 남의 서버를 두드리는 일이다

- **하루 1회**로 충분하다. 법령은 그보다 자주 안 바뀐다
- `If-Modified-Since` / `ETag` 를 보내고 **304 면 본문을 받지 않는다**
- 실패하면 **지수 백오프**. 계속 실패하면 사람에게 알리고 멈춘다
- User-Agent 에 연락처를 남긴다

## 구현

| | |
| --- | --- |
| 레지스트리 | [`BE/data/official-sources.json`](../../../BE/data/official-sources.json) — 사람이 관리 |
| 감시 스크립트 | `BE/scripts/watch-sources.mjs` — BE 이미지에 담겨 서버에서 돈다 |
| 상태(기준선) | `BE/data/source-state.json`(로컬) · named volume `konnect-source-state`(서버) — **커밋하지 않는다** |
| 스케줄 | `deploy/a1-watch-sources.sh` — **A1 서버 cron**, 매일 09:00 KST |
| 알림 | 변경 시 **이슈 생성** — "봤다/안 봤다"가 추적되어야 한다 |

### 왜 레지스트리가 `contracts/` 가 아닌가

한동안 `contracts/official-sources.json` 이었다. 그런데 그 폴더는
[FE 와 BE 가 **같아야 하는** 규칙의 자리](../../../contracts/README.md)이고, 이 파일은
FE 가 읽지 않으며 양쪽을 대조하는 테스트도 없다 — 계약이 아니라 BE 의 입력이었다.

옮긴 결정적인 이유는 따로 있다. BE 이미지의 **빌드 컨텍스트가 `BE/`** 라
([deploy.yml](../../../.github/workflows/deploy.yml)) 저장소 루트의 파일은 이미지에
담을 수가 없다. 서버에서 감시를 돌리려면 레지스트리가 `BE/` 안에 있어야 한다.

### 상태 파일을 커밋하지 않는 이유

해시는 **파생 데이터**다 — 원문에서 언제든 다시 만들 수 있다. 커밋하면 두 가지가 따라온다.

1. 감시가 **저장소 쓰기 권한**을 요구한다. 프로덕션에 push 권한을 두는 것은
   배포 키에 `command=` 제약을 걸어 셸조차 막아 둔 방향과 정반대다
2. 낡은 기준선이 **거짓 "변경됨"** 을 만든다

서버에서는 named volume 에 둔다. 지워져도 다음 실행이 "최초 기록"으로 다시 만든다
(그 한 번은 변경을 감지하지 못한다 — 그게 유일한 대가다).

## 배포 — 서버에서 어떻게 도나

```
cron(09:00 KST) → /srv/app/konnect/watch-sources.sh
                     └─ docker compose run --rm watch-sources
                          ├─ 이미지: konnect-be (scripts/ + data/ 포함)
                          ├─ 읽기: /app/data/official-sources.json   ← 이미지
                          └─ 쓰기: /app/var/source-state.json        ← named volume
```

**GitHub Actions 가 아니라 서버인 이유**는 법제처 API 가 호출 IP 를 사전 등록하게 하기
때문이다(아래 "겪은 함정"). 러너 IP 는 매번 바뀐다.

**A1 에 저장소 체크아웃을 두지 않는 이유**는 그 서버가 이미지만 받아 실행하도록
설계됐기 때문이다. 감시 하나 때문에 프로덕션에 git 과 push 권한을 들이지 않는다 —
스크립트를 이미지에 넣으면 `migrate` 와 **같은 패턴**이 된다.

⚠️ 볼륨을 `/app/data` 에 걸면 **이미지 안의 레지스트리가 가려진다.** 그래서 읽기(`/app/data`)와
쓰기(`/app/var`)를 다른 디렉터리로 나누고 `KONNECT_SOURCE_STATE` 로 가리킨다.

### 만들면서 잡은 함정

**에러 페이지를 정상으로 세고 있었다.** 하이코리아는 없는 주소에 **200 으로 에러
페이지**를 돌려준다. 그대로 해시하니 매일 "변동 없음"이 찍혔다 —
**에러 페이지를 안정적으로 감시하는** 상태였다. 텍스트가 147자뿐인 것을 보고 알았다.

가드를 넣었다: **본문 400자 미만**이거나 **에러 문구**가 있으면 실패로 처리한다.
잘못된 URL 로 되돌려 확인했더니 정확히 그 건만 실패했다.

**해시가 매일 흔들리면 감지가 무의미해진다.** 조회수·현재시각 같은 토큰이
본문에 섞여 있어, 해시 전에 **날짜·시각 패턴을 제거**한다. 2회 연속 실행해
"변동 없음"이 나오는 것을 확인했다.

**변경과 실패를 구분한다.** 변경은 정상이고(종료코드 0), 수집 실패만 1 이다 —
그래야 cron 메일이 "바뀜"이 아니라 "못 가져옴"에만 온다.

**법령 본문이 455KB 라 해시가 흔들릴 위험이 컸다.** 3회 연속 실행해
"변동 없음"이 나오는 것을 확인했다 — 날짜·시각 토큰 제거가 실제로 듣는다.

## 열린 질문

- 하이코리아 안내문의 이용 조건(KOGL 유형)을 확인하지 않았다 — **링크만 두는 것이 안전하다**
- 공지사항 중 **어떤 것이 어느 비자에 영향을 주는지**는 자동으로 못 가른다.
  지금은 제목 키워드 매칭이고, 이건 정확하지 않다
- 출처가 바뀌었을 때 **누가 확인하나?** 전문가가 없으면 배지만 붙고 글은 안 고쳐진다 —
  그 상태를 사용자에게 정직하게 보여야 한다("출처가 바뀌었으나 아직 확인되지 않음")

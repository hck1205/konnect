# 게시글 작성

> 우선순위 **P0** · [Q&A](./02-qna.md)의 입력 경로

## 왜 가장 중요한 UX 지점인가

여기서 **공급이 결정된다.** 질문이 안 올라오면 커뮤니티가 없다.

동시에 상충하는 요구가 있다:

- **태그를 요구하면** 마찰이 생겨 이탈한다
- **안 받으면** 매칭이 안 된다. 태그는 P0 이고 **소급 적용이 불가능하다** —
  태그 없는 글 1000개가 쌓인 뒤 태그를 도입하면 그 1000개는 영원히 매칭에서 빠진다
  ([핵심 기능](../02-core-features.md))

## 마찰을 줄이는 방법

강제가 아니라 **가치를 먼저 준다.**

| 장치 | 효과 |
| --- | --- |
| **작성 중 비슷한 질문 표시** | 중복을 막고, "이미 답이 있다"는 즉각적 가치를 준다. 태그를 강제하는 것보다 효과가 크다 |
| 본문에서 태그 자동 감지 | `D-2` 를 쓰면 `visa:d-2` 를 제안한다 |
| 주제는 필수, 맥락 태그는 강력 권장 | 최소한만 막는다 |
| 제목 작성 유도 | 제목이 곧 검색어가 된다 |

## 구성

```
제목        필수. 구체적인 질문 형태를 예시로 보여준다
비슷한 질문  제목을 쓰는 동안 나타난다
본문        작성 / 미리보기 전환
태그        최대 5개
액션        취소 · 임시저장 · 등록
```

미리보기를 **탭이 아니라 SegmentedControl** 로 둔다 —
탭은 화면 영역을 바꾸는 내비게이션이고, 이건 **입력 모드 선택**이다
([컴포넌트](../../25-design/20-components/)).

## 본문 형식 — 미정

마크다운과 WYSIWYG 중 정해지지 않았다.

- **마크다운**: 저장이 단순하고 이식성이 높다. 다만 대상 사용자 상당수가 마크다운을 모른다
- **WYSIWYG**: 배우기 쉽지만 저장 형식·정화(sanitize)·붙여넣기 처리가 복잡해진다

지금은 **평문 + 줄바꿈 보존**이고 `Prose` 가 렌더를 맡는다.
형식이 정해지면 미리보기와 렌더만 바꾸면 된다.

## 열린 질문

- 본문 형식 확정
- 이미지 업로드 — 서류 스크린샷이 실제로 유용하지만, **개인정보가 찍혀 올라온다.**
  올리기 전 경고와 가림 처리가 필요하다
- 임시저장을 서버에 둘 것인가 로컬에 둘 것인가?

# 가이드 (위키)

> 우선순위 **P1** · Q&A가 쌓인 뒤에 의미가 생긴다

## 목적

반복되는 질문을 **한 번 잘 정리해** 다음 사람이 질문할 필요조차 없게 만든다.
[제품 원칙 1](../../00-overview/02-problem-statement.md)의 구현체.

## 승격 흐름

```
Question (여러 개, 같은 주제)
  → 누군가 "가이드로 만들자" 제안
  → 가이드 작성 (기존 Q&A를 출처로 링크)
  → 원 질문들에 "관련 가이드" 배지
```

## 모델

```
Guide
  title, body, topic, tags[]
  sources[]          ← 공식 출처 링크 (R1은 필수)
  lastVerifiedAt     ← 최신성 — 이 영역의 핵심 필드
  revisions[]        ← 편집 이력 (누가, 언제, 무엇을)
```

## 최신성 (freshness)

가이드의 **가장 큰 위험은 오래되는 것**이다. 절차는 바뀌는데 문서는 그대로 남는다.

- `lastVerifiedAt`을 콘텐츠 상단에 **항상 표시**한다
- 일정 기간이 지나면 UI에 경고 배지 ("이 정보는 N개월 전에 확인되었습니다")
- "아직 유효함" 버튼으로 사용자가 갱신할 수 있게 (누가 확인했는지 기록)

## 편집 권한

| 안 | 장점 | 단점 |
| --- | --- | --- |
| 누구나 편집 (위키형) | 축적이 빠르다 | 훼손·오정보 위험 |
| 평판 기준 이상만 | 품질 방어 | 초기에 편집자가 없다 |
| 제안 후 승인 | 안전 | 운영 부담 |

→ **제안 후 승인**으로 시작하고, 평판 기능이 생기면 완화하는 안이 유력 (열린 질문)

## 열린 질문

- 편집 권한 모델 확정
- 가이드와 체크리스트의 관계 — 체크리스트 항목이 가이드를 가리키는 구조인가?
- 다국어 가이드를 **번역본으로** 둘 것인가, 언어별 독립 문서로 둘 것인가?
  → [i18n 전략](../../30-architecture/06-i18n-strategy.md)

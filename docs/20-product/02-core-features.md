# 핵심 기능

## 목록과 우선순위

`P0` = MVP 필수, `P1` = MVP 직후, `P2` = 이후

| 우선 | 기능 | 왜 |
| --- | --- | --- |
| P0 | **인증** (소셜 로그인) | 글을 쓰려면 필요. 가입 마찰 최소화가 관건 |
| P0 | **Q&A** (질문/답변/채택) | 커뮤니티의 심장 |
| P0 | **태그** (고정 어휘 + 자유 태그) | 맥락 매칭의 기반 — 나중에 넣으면 기존 글이 전부 태그 없이 남는다 |
| P0 | **검색** | 검색이 안 되면 축적이 무의미하다 |
| P0 | **신고/모더레이션** | 안전은 나중이 아니다 |
| P0 | **프로필** | 누가 답했는지 = 신뢰 |
| P1 | **가이드** (승격·편집) | 축적의 본체. 단, Q&A가 쌓여야 승격할 게 생긴다 |
| P1 | **체크리스트** | 초기 정착 문제의 직접 해법. 콘텐츠 제작 비용이 큼 |
| P1 | **알림** | 답변이 달렸는지 알아야 재방문한다 |
| P1 | **게시판/피드** | 질문이 아닌 글의 자리 |
| P2 | **평판** | 기여 동기. 사용자가 적을 땐 의미 없다 |
| P2 | **밋업** | 안전 장치가 먼저 |
| P2 | **다국어 UI** | 영어로 시작. [i18n 전략](../30-architecture/06-i18n-strategy.md) |
| P2 | **북마크/저장** | 있으면 좋지만 없어도 성립 |

## 왜 태그가 P0인가

기능 중 **유일하게 나중에 추가하기 어려운 것**이다.
검색·알림·평판은 나중에 붙여도 기존 데이터에 소급 적용되지만,
태그는 **작성 시점에 사람이 입력**하는 정보라 소급이 불가능하다.
태그 없는 글 1000개가 쌓인 뒤 태그를 도입하면 그 1000개는 영원히 매칭에서 빠진다.

## 왜 평판이 P2인가

평판은 **사용자 수의 함수**다. 10명이 쓰는 서비스에서 점수는 의미가 없고,
오히려 초기 기여자에게 "내 점수가 낮다"는 부정적 신호만 준다.

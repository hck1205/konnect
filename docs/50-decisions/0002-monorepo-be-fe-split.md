# ADR-0002 · 한 저장소에 BE/ · FE/ 를 분리해 둔다

- **상태**: 수락됨
- **날짜**: 2026-08-24

## 맥락

FE(Next.js)와 BE(NestJS)를 어떻게 배치할지 정해야 한다.
둘은 **배포 단위가 다르고**(FE는 SSR 서버, BE는 API 서버), 의존성 트리도 완전히 별개다.
동시에 **API 계약을 공유**하므로 함께 바뀌는 일이 잦다.

## 결정

**하나의 저장소에 `BE/`와 `FE/` 두 디렉터리를 두고, 각각 독립적인 npm 프로젝트로 관리한다.**

- 루트에 워크스페이스(npm workspaces / turborepo)를 두지 **않는다**
- 각 디렉터리가 자기 `package.json`, `node_modules`, lockfile, 설정을 갖는다
- 루트 `.gitignore`는 화이트리스트 방식으로 `docs/`, `FE/`, `BE/`, `README.md`만 추적한다

## 결과

**좋은 점**
- API 계약이 바뀔 때 **한 커밋/한 PR**로 양쪽을 고칠 수 있다. 이게 가장 큰 이득이다
- 배포는 여전히 독립적이다 (디렉터리별로 빌드)
- 워크스페이스 도구의 복잡도(호이스팅 문제, 빌드 순서, 도구 학습)를 지지 않는다

**비용**
- 공유 타입을 **코드로 공유하지 못한다.** 응답 타입을 양쪽에 각각 적어야 한다
  → 지금은 감수한다. 계약이 커지면 `packages/shared`를 만드는 ADR을 새로 쓴다
- 의존성이 중복 설치된다 (디스크·설치 시간)

## 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| **저장소 2개로 분리** | 계약 변경이 2개 PR로 갈라진다. 초기 속도에 치명적 |
| **npm workspaces / turborepo** | 지금 규모(앱 2개)에서 얻는 게 적고, 도구 복잡도가 먼저 온다. 필요해지면 나중에 도입 가능 |
| **단일 Next.js 풀스택 (API Routes)** | 도메인 모듈 경계가 약하고, BE를 독립 확장하기 어렵다 |

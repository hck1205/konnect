# ADR-0009 · 국적은 상시 표시하지 않고, 필요한 맥락에서만 보인다

- **상태**: 수락됨
- **날짜**: 2026-08-27
- **관련**: [ADR-0008](./0008-nationality-as-tag-not-space.md)의 열린 질문
  **"국적이 드러나면 차별 대상이 될 수 있다"**에 답한다.

## 맥락

"카테고리로 나누지 않는 대신 **사용자 이름 옆에 국적을 표시**하자"는 제안이 나왔다.
[ADR-0008](./0008-nationality-as-tag-not-space.md)이 포기한 것
(**국적별 소속감**)을 보완하려는 시도이고, 목표는 정당하다.

### 목표를 두 개로 분리해야 한다

| 목표 | 국적이 실제로 답하는가 |
| --- | --- |
| **(A) 신뢰** — "이 답을 믿어도 되나" | **부분적으로만** |
| **(B) 연결** — "같은 처지 사람을 찾고 싶다" | **글 태그로 이미 된다** |

**(A)에는 국적보다 잘 듣는 신호가 있다.**

| 신호 | 왜 더 나은가 |
| --- | --- |
| **해당 경험 보유** ("F-2 취득함") | **가장 강하다.** 질문과 직접 대응한다 |
| 체류 연차 ("한국 8년차") | 국적보다 답변 신뢰와 직접 관련 |
| 평판 (채택된 답변) | 행동 기반이라 검증된다 |
| **사용 언어** | 이미 [프로필 공개 항목](../20-product/10-features/04-profiles-and-reputation.md)이다 |

**(B)는 이미 해결돼 있다.** `nationality:` 태그가 붙은 **글**을 찾으면 된다.

### 기존 결정과 충돌한다

이 제안은 이미 정해진 두 가지와 부딪힌다.

- [프로필 문서](../20-product/10-features/04-profiles-and-reputation.md)의
  **"담지 않는 것(기본값)"** 목록에 국적이 있다
- [안전 문서](../10-domain/60-social-community/02-safety-and-trust.md)가
  **"괴롭힘·차별 — 국적·인종 기반 혐오"** 를 위협 유형으로 이미 잡아 뒀다

**상시 표시는 우리가 방어 대상으로 지목한 것을 상시 노출하는 것**이 된다.

### 왜 상시 표시가 특히 위험한가

1. **차별 경험이 19.7%** 인 집단이다 (직장 41.7%).
   이름 옆에 국적이 있으면 **답을 읽기 전에 국적을 먼저 본다**
2. **선택 표시로 만들어도 안전해지지 않는다.**
   대부분이 표시하면 **표시하지 않은 사람이 오히려 의심받는다** — 선택제의 함정이다
3. **되돌리기 어렵다.** ADR-0008 은 "태그는 되돌리기 쉽다"였는데
   **상시 표시는 규범이 되면 없애기 어렵고, 없애면 "왜 숨기냐"가 된다**
4. **익명성 정책과 충돌한다.** 실명 인증을 하지 않기로 한 이유가
   [신원 노출이 곧 위험인 사용자](../20-product/20-prd/04-requirements.md)가 있어서다.
   국적은 강한 식별자이고, ADR-0008 이 이미 우려한 조합
   (`nationality:mn` × `region:영암` × `visa:e-9`)이 **자동으로 노출된다**
5. **검증할 수 없다.** 실명 인증을 안 하니 국적도 자기 신고다.
   신뢰 신호로 쓰면 **검증되지 않은 신뢰**를 만든다 — 없느니만 못하다

## 결정

**국적은 상시 표시하지 않는다. 국적이 실제로 답에 영향을 주는 맥락에서만 보인다.**

| 위치 | 표시 |
| --- | --- |
| 목록·피드의 작성자 | **표시하지 않는다** |
| 답변 옆 작성자 (일반 글) | **표시하지 않는다** |
| **답변 옆 작성자 (`nationality:` 태그가 붙은 글)** | **표시한다** — 사용자가 공개를 선택한 경우 |
| 프로필 페이지 | 선택 공개. **기본값은 비공개** |
| **국기 아이콘** | **쓰지 않는다** (아래) |

### 맥락 의존 표시가 핵심이다

같은 정보라도 맥락에 따라 값이 다르다.

> **"베트남 범죄경력증명서 아포스티유 어떻게 받나요"**
> → 답변자가 베트남 국적인지가 **정말 중요하다.** 그게 곧 자격이다

> **"F-2-7 점수 계산이 맞나요"**
> → 답변자 국적은 **아무 의미가 없다.** 보이면 편견만 만든다

**글에 `nationality:` 태그가 있을 때만 답변자 국적 배지를 렌더링한다.**
구현은 단순하고, 국적이 값을 갖는 곳에서만 값을 준다.

### 국기 아이콘을 쓰지 않는 이유

- **정치적이다.** 어떤 깃발을 쓰느냐가 분쟁이 되는 경우가 실재한다
- **시각적으로 너무 강하다.** 텍스트보다 먼저 눈에 들어와 편견을 앞당긴다
- 필요하면 **국가명 텍스트**로 쓴다

### 대신 "사용 언어"를 쓴다

연결 목적에는 **사용 언어가 국적보다 낫다.**

- **대화 가능 여부를 직접 말해 준다** — 국적은 그것의 대리 지표일 뿐이다
- 러시아어를 쓰는 우즈벡·카자흐·러시아 사용자를 **하나로 묶는다**
- 차별 축으로 덜 쓰인다 (안전하다는 뜻은 아니다)
- **이미 프로필 공개 항목에 있다.** 새로 만들 것이 없다

## 결과

**좋은 점**
- 차별 축을 상시 노출하지 않는다 — 안전 문서가 지목한 위협을 키우지 않는다
- **국적이 진짜 필요한 질문에서는 여전히 보인다** (아포스티유·본국 서류)
- 되돌리기 쉽다. 맥락을 넓히는 것은 쉽고, 상시 표시를 걷어내는 것은 어렵다
- 익명성 정책과 충돌하지 않는다

**비용**
- **"같은 나라 사람"을 한눈에 알아보지 못한다.** ADR-0008 이 포기한 소속감을
  이번에도 완전히 회복하지 못한다 — 부분적으로만 보완한다
- 맥락 의존 표시는 **조건 분기**라 상시 표시보다 구현이 조금 복잡하다
- `nationality:` 태그가 안 붙은 글에서는 국적 정보가 필요해도 안 보인다
  → **태그를 잘 붙이게 하는 것이 전제**가 된다

## 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| **이름 옆 상시 표시 (제안)** | 차별 축 상시 노출. 되돌리기 어렵다. 검증도 안 된다 |
| 아이디 자체에 국적 포함 (`minh_vn`) | 상시 표시보다 더 나쁘다 — **변경조차 불가능**하고 계정 이관이 안 된다 |
| 선택 표시 (기본 노출, 끌 수 있음) | **끈 사람이 의심받는다.** 선택제가 아니라 사실상 강제다 |
| 아예 국적을 안 다룬다 | 아포스티유·본국 서류처럼 **진짜 국적별인 답**을 못 찾는다 |

## 열린 질문

- `nationality:` 태그가 붙은 글에서 **작성자가 공개를 선택하지 않았다면** 무엇을 보이나?
  (아무것도 안 보이는 것이 맞아 보이지만, 그러면 공개한 사람만 신뢰를 얻는다)
- 맥락 의존 표시가 **실제로 이해되는가?** "왜 어떤 글에서만 보이지?"
  → 설명이 필요하다면 그 자체가 설계 실패 신호다
- 사용 언어 표시도 차별 축이 될 수 있다. 어디까지가 안전한가?

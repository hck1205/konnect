# ADR-0008 · 국적으로 공간을 나누지 않는다 — 태그로 붙인다

- **상태**: 수락됨
- **날짜**: 2026-08-27
- **관련**: [ADR-0007](./0007-settlement-intent-as-primary-axis.md)의 비치헤드 논리를 지킨다.

## 맥락

"국가별로 카테고리를 나눠 교류를 활발하게 하자"는 제안이 나왔다.
**이유는 타당하다** — 언어·문화가 다르면 교류가 활발하지 않을 것이다.

진단은 맞다. 처방을 검토한 결과 **한 부분이 어긋난다.**

### 1. 장벽은 국적이 아니라 언어다. 그리고 국적은 언어의 나쁜 대리 지표다

| 언어 | 해당 국적 |
| --- | --- |
| `ru` | 우즈베키스탄 · 카자흐스탄 · 러시아 — **3개국이 한 언어** |
| `en` | 미국 · 캐나다 · 필리핀 · 인도 · 나이지리아 … — **다수 국적이 한 언어** |
| `ko` | **한국계중국인(조선족)** — 중국 국적이지만 한국어를 쓴다 |

**국적으로 나누면 통하는 사람들을 갈라놓는다.** 우즈벡·카자흐 사용자는
러시아어로 대화가 되는데 다른 방에 있게 된다. 우리는 이미 **언어 축을 갖고 있고**
([ADR-0005](./0005-multilingual-from-day-one.md)), 그것이 더 정확한 축이다.

### 2. 비치헤드의 존재 이유를 스스로 파괴한다

[ADR-0007](./0007-settlement-intent-as-primary-axis.md)이 영주·귀화 준비자를 고른
결정적 이유가 **"국적을 안 가려서 하나의 콘텐츠가 모든 정주 세그먼트에 닿는다"**
였다. 언어별 임계질량을 각각 넘지 않아도 되는 것이 이 타깃의 핵심 이점이다.

**국가별로 방을 나누면 그 이점이 사라진다.** 최대 리스크가
[빈 커뮤니티](../20-product/20-prd/06-risks-and-open-questions.md)인 상황에서
모수를 국가 수만큼 쪼개는 것은 반대 방향이다.

### 3. 원래 목적과 반대다

이 서비스의 출발점은 **"서로 교류하는 사이트"**였다.
국가별로 나누면 **각 국가 커뮤니티의 집합**이 되고, 그것은
**이미 Facebook 그룹·Zalo 가 하고 있는 것**이다. 우리가 이길 이유가 사라진다.

### 4. 국적 기반 분리는 이 맥락에서 특히 위험하다

- 차별 경험이 **19.7%** 인 집단이다. 국가별 방은 "우리 vs 저들" 구도를 만들기 쉽고,
  국가 간 역사·정치 갈등이 그대로 들어온다
- **모더레이션 비용이 국가 수만큼 늘어난다.** 각 방의 언어를 읽을 사람이 필요한데
  [신고 처리 인력조차 없다](../20-product/20-prd/07-monetization.md#비용이-이제-제약이다)

### 5. 그런데 국적이 실제로 필요한 곳이 있다

전부 부정하면 틀린다. **답이 진짜 국적별로 다른 정보가 있다.**

- 국가별 협정(H-1 관광취업), 병역·이중국적
- 아포스티유 / 영사확인 절차
- 본국 서류(범죄경력증명서·출생증명서·학력) 발급 방법 — **영주·귀화 신청의 핵심 서류다**

그리고 **친구·모임은 모국어로 하고 싶은 것이 자연스럽다.**

### 6. 정주자에게는 언어 장벽이 생각보다 낮다

비치헤드인 영주·귀화 준비자는 체류 5년차 이상이고
**KIIP·TOPIK 이 요건이라 한국어를 공부해야만 하는 사람들**이다.

즉 "언어 때문에 교류가 안 될 것"이라는 걱정은
**유학생 1년차에게는 맞지만 이 세그먼트에서는 덜 맞다.**
타깃을 정주자로 옮긴 결정이 이 문제를 상당 부분 이미 해결했다.

## 결정

**국적은 `nationality:` 고정 어휘 태그로 붙이고, 전용 공간(카테고리)으로 나누지 않는다.**

| | 카테고리(공간) | **태그(속성)** |
| --- | --- | --- |
| 효과 | 사람이 **흩어진다** | 하나의 공간에서 **좁혀 본다** |
| 빈 방 | **생긴다** | 없다 |
| 임계질량 | 각각 넘어야 한다 | **한 번만 넘으면 된다** |
| 되돌리기 | 어렵다 (합치는 것이 더 아프다) | 쉽다 |

- 태그 네임스페이스에 **`nationality:`** 를 추가한다 (고정 어휘, 관리자 관리)
- **교차 필터는 BE 가 이미 지원한다** — `nationality:vn` × `topic:residency` 가 바로 된다
- **`topic:`** 도 함께 추가한다 (`residency` `work` `housing` `admin` `language`) —
  [09-content-pillars](../20-product/20-prd/09-content-pillars.md)가 요구한 것이다

### 공간으로 승격하는 기준

태그가 자라면 전용 공간이 될 수 있다. **감이 아니라 숫자로 판정한다.**

> 해당 태그의 **주간 신규 글이 4주 연속 10건 이상**이고,
> **답변률이 전체 평균 이상**일 때만 승격한다.

이 기준은 **"빈 방을 만들지 않는다"를 자동으로 보장한다.**
학교 태그·지역 태그에도 같은 규칙을 적용한다
([이전에 같은 결론을 냈다](../20-product/20-prd/02-segments-and-priority.md)).

### 교류(관계) 축은 예외다 — 단 지금이 아니다

**정보는 한 공간이 맞지만, 친구·모임은 실제로 모여야 한다.**
여기서는 국적·언어 기반 그룹이 옳을 수 있다.

다만 [친구·모임은 P1 이고 Phase 1 이 아니며](../20-product/20-prd/03-interests-and-jobs.md),
DM·모임은 [안전장치와 신고 처리 인력이 전제](./0004-direct-messages-with-safety-gates.md)인데
**지금 그 인력이 없다.** 즉 **국적별 공간이 필요해지는 시점은 아직 오지 않았다.**

### 교류를 활발하게 하는 더 나은 축

국적 분리는 수단이지 목적이 아니다. 목적은 "대화가 되게" 하는 것이고,
**더 잘 듣는 축이 있다.**

| 축 | 왜 더 나은가 |
| --- | --- |
| **같은 처지** (`F-2 준비 중` · `3년차` · `아이 있음`) | 베트남 사람과 몽골 사람도 **"F-2-7 점수" 얘기는 통한다.** 국적보다 대화가 된다 |
| **지역** (`region:안산`) | **만나려면 같은 동네여야 한다.** 정주자에게 가장 강한 축이다 |
| **언어** | 이미 있다. 국적보다 정확하다 |
| **한국어를 공통어로** | 정주자는 한국어를 한다. 비치헤드의 숨은 이점이다 |

## 결과

**좋은 점**
- 모수가 쪼개지지 않는다 — 최대 리스크(빈 커뮤니티)를 키우지 않는다
- **국적이 필요한 정보는 여전히 필터로 찾을 수 있다** (아포스티유·본국 서류 등)
- 되돌리기 쉽다. 태그는 나중에 공간으로 승격할 수 있지만 그 반대는 아프다
- 모더레이션 대상이 하나로 유지된다

**비용**
- **국적별 소속감이 약하다.** "내 나라 사람들 방"이 주는 심리적 안정감을 포기한다
- 모국어로 편하게 이야기하고 싶은 수요를 **당장은 충족하지 못한다**
  → 관계 축을 열 때 다시 본다. 미루는 것이지 부정하는 것이 아니다
- 필터를 쓸 줄 알아야 국적별 정보에 닿는다 — **발견성 설계가 필요하다**

## 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| **국가별 카테고리 (제안)** | 모수를 쪼갠다. 비치헤드의 이점을 파괴한다. Facebook 그룹과 같아진다 |
| 언어별 카테고리 | 국적보다는 낫지만 여전히 공간을 나눈다. **언어는 이미 UI 로케일과 작성 언어 태그로 다룬다** |
| 국적 태그를 아예 안 만든다 | 아포스티유·본국 서류처럼 **진짜 국적별인 정보**를 못 찾게 된다 |
| 지금 국적별 모임 그룹을 연다 | 안전장치·신고 인력이 없다. [ADR-0004](./0004-direct-messages-with-safety-gates.md) 위반이다 |

## 열린 질문

- `nationality:` 태그를 **프로필에서 자동 제안**할 것인가?
  편하지만 **민감정보**이고, 국적이 드러나면 차별 대상이 될 수 있다 → 선택 입력·표시 선택
- 국적 태그로 **작성자를 특정할 수 있는 조합**이 생기지 않는가?
  (`nationality:mn` × `region:영암` × `visa:e-9` 는 몇 명인가)
- 승격 기준의 "주 10건"이 맞는 숫자인가? **근거 없는 초기값이다** — 운영하며 조정한다

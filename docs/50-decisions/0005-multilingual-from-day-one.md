# ADR-0005 · 다국어를 출시 시점부터 지원한다

- **상태**: 수락됨
- **날짜**: 2026-08-24
- **관련**: [ADR-0003](./0003-english-first-multilingual.md)의 **"MVP 는 영어 단일"** 부분을 대체한다.
  ADR-0003 의 나머지(영어를 기준 언어로, 사용자 콘텐츠는 번역하지 않음, 한국어 원문 병기)는 **그대로 유효하다**.

## 맥락

ADR-0003 은 "MVP 는 영어 단일 UI 로 내되 문구를 하드코딩하지 않는다"고 정했고,
다국어 UI 는 [P2](../20-product/02-core-features.md)였다.

제품 요구가 바뀌었다: 이 서비스는 **여러 나라 사용자를 동시에** 대상으로 한다.
영어 단일로 출시하면:

- 영어가 불편한 사용자가 첫 화면에서 이탈한다. 그런데 이들이야말로
  정보 접근이 가장 어려운 — 즉 이 서비스가 가장 필요한 — 사람들이다
- 검색 유입이 영어권으로만 잡힌다. 언어별 색인 기회를 통째로 잃는다
- "나중에 추가"는 실제로는 안 된다. 문구가 화면 수십 개에 흩어진 뒤에는
  추출 비용이 기능 개발 비용을 넘는다

## 결정

**출시 시점부터 다국어를 지원한다.**

- 지원 로케일: `en`(기준) · `ko` · `zh` · `vi`. 구조는 추가에 열려 있다
- **로케일은 URL 세그먼트**다 (`/ko/questions/123`). 쿠키가 아니다 —
  언어별 고유 URL 이 있어야 검색엔진이 언어별로 색인한다. 쿠키 기반이면
  같은 URL 이 사람마다 다른 언어를 보여줘 색인이 하나로 뭉개진다
- 로케일 세그먼트가 없는 요청은 **`Accept-Language` 로 협상**해 리다이렉트한다(307).
  처음 방문한 사람이 자기 언어를 직접 찾아야 하는 상황을 없앤다
- 복수형은 **`Intl.PluralRules`** 에 맡긴다. 언어마다 카테고리가 다르다 —
  영어는 둘, 한국어는 하나, 아랍어는 여섯이다. 우리가 규칙을 갖고 있으면 안 된다
- 숫자·통화·날짜·목록 나열도 전부 `Intl` 이다. 베트남어 천 단위 구분자는 마침표(`1.234.567`)다

### 라이브러리를 쓰지 않고 얇은 계층을 직접 만든 이유

`Intl` 이 **어려운 부분(복수 규칙, 포맷)을 이미 한다.** 남는 것은 보간·폴백·사전
조회이고 그건 100줄 남짓이다. 대신 얻는 것:

- Ladle 스토리가 별도 설정 없이 동작한다
- 번들에 파서가 들어가지 않는다
- 폴백 규칙이 우리 눈에 보인다(누락 키가 **키 그대로** 화면에 뜬다 — 빈 문자열이면 못 본다)

사전이 커지거나 번역 도구 연동이 필요해지면 `next-intl` 등으로 옮긴다.
그때 바뀌는 것은 `lib/i18n` 안쪽이고, 컴포넌트는 `t()` 만 쓰므로 영향이 적다.

## 결과

**좋은 점**
- 타깃 사용자가 자기 언어로 첫 화면을 만난다
- 언어별 검색 색인이 잡힌다
- 문구가 처음부터 사전에 모여 있어 언어 추가가 파일 추가로 끝난다

**비용**
- 화면을 만들 때마다 문구를 사전에 추가해야 한다. 하드코딩보다 느리다
- **번역 품질 부채가 생긴다.** 현재 `zh`·`vi` 는 원어민 검수 전이고,
  행정 용어 오역은 R1 영역에서 실제 피해가 된다
  ([리스크 정책](../10-domain/10-visa-immigration/03-content-and-risk-policy.md)).
  **출시 전 검수는 선택이 아니다**
- 로케일 라우팅이 모든 링크에 영향을 준다(`/ko/...` 접두사)

## 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| **영어 단일로 출시 후 추가** (기존 계획) | "나중에"가 실제로는 안 된다. 문구가 흩어진 뒤 추출 비용이 기능 비용을 넘는다 |
| 쿠키/헤더 기반 언어 전환 (URL 동일) | 검색엔진이 언어별로 색인하지 못한다. 유입이 주 채널인데 치명적이다 |
| 자동 기계 번역 전면 적용 | 행정·법률 용어 오역이 곧 피해다. ADR-0003 이 이미 배제했고 그 판단은 유효하다 |
| `next-intl` 도입 | 지금 규모에서 얻는 것이 적다. `Intl` 이 어려운 부분을 이미 한다. 필요해지면 옮긴다 |

## 열린 질문

- `zh`·`vi` 원어민 검수를 누가 언제 하는가? **출시 차단 조건이다**
- 로케일별 사전을 동적 import 로 분리할 시점 — "번들에서 사전이 눈에 띌 때"
- 사용자 콘텐츠(질문·답변)에 **작성 언어 태그**를 붙여 필터링할 것인가?
